# 风险管理计划（MAN.5）

> 自动生成：本计划的评分方法与阈值由 `step_handlers/risk.py` 维护，人工修订请直接编辑本文件。

## 风险管理范围

- 覆盖产品确认前的全部工程活动：需求、架构、实现、测试、发布。
- 风险来源：MAN.6 度量 FAIL 项、流水线步骤失败记录、人工登记条目。
- 责任人：项目负责人（MAN.3）对风险清单整体负责。

## 风险评分方法

评分 = 可能性(L) × 影响(I)，两者取值 1-5：

| 分值 | 等级 | 处置要求 |
|:---|:---|:---|
| 15-25 | critical | 必须制定规避/转移方案，项目级升级，每周评审 |
| 8-14 | high | 必须指定责任人并给出缓解措施，双周评审 |
| 4-7 | medium | 纳入常规跟踪，月度评审 |
| 1-3 | low | 记录并接受，阶段评审时复核 |

应对策略：`avoid` 规避 / `mitigate` 缓解 / `transfer` 转移 / `accept` 接受（选 accept 必须填写 `rationale`）。

## 评审与升级

- 高风险（score ≥ 8）开放项必须在 `docs/risk-register.yaml` 中登记责任人、缓解措施与到期评审日（`review_due`, YYYY-MM-DD）。
- 自动识别的风险在人工指定责任人前标记为「待分级」，列入风险报告「升级项」，由项目负责人分级后方视为已处置。
- 状态流转：open → monitoring → mitigated → closed，仅允许人工修改。
- 升级路径：责任人 → 项目负责人 → 质量负责人。
