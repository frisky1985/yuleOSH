# ASPICE 4.0 CL2 新增模板说明

本说明对应《ASPICE4.0_CL2_过程-证据覆盖矩阵.xlsx》sheet「3-缺口清单」中的 4 项 P0 缺口。4 份模板均放在 `templates_new/`，字段口径与覆盖矩阵 sheet「2-过程-证据矩阵」保持一致，版式沿用 `_source_templates` 的封面（B 列标签 / C 列填写值）+ 变更履历 + 编号章节 sheet 语言。

## 一、MAN.5_风险登记册_V1.0.xlsx

**对应缺口：** P0 序号 45，过程域 MAN.3，证据要求「风险管理（识别/评估/措施/跟踪）」，判定「缺失」。

> 原缺口文字：无风险登记册、无风险评估准则、无风险评审记录——MAN.5 完全缺位；这是 CL2 最容易被打 N 的缺口

> 补齐动作原文：新建风险登记册（含可能性/影响/等级/措施/责任人/关闭）＋季度风险评审记录

**补齐字段（5 个业务 sheet，共 4+5+6+4+4 张表 / 16 个登记字段）：**

- `1.风险评估准则`：可能性等级 1–5（等级定义/概率区间/判定依据）；影响等级 1–5（进度/成本/质量/安全四维）；5×5 风险等级矩阵（可能性×影响→低/中/高/严重）；风险等级判定规则（1–4 低、5–9 中、10–16 高、17–25 严重）；处置策略（规避/减轻/转移/接受）。
- `2.风险登记册`：风险ID、风险类别（技术/资源/供应链/需求/质量/安全）、风险描述、触发条件、可能性、影响、风险等级（`IF/IFERROR` 公式，自动由可能性×影响映射文字）、处置策略、应对措施、责任人、计划关闭日期、实际关闭日期、状态（开放/缓解中/已关闭/已发生）、关联问题ID（SUP.9）、关联变更ID（SUP.10）、备注。
- `3.风险评审记录`：评审日期、参与人、新增风险数、升级风险数、关闭风险数、剩余高风险数、决策与行动、下次评审日期。
- `4.风险趋势`：月份、新增、关闭、剩余（累计公式）、其中高风险数。

**外键关联：**

- `2.风险登记册·关联问题ID` → 《亚远景_SUP9_TP_缺陷问题管理表》sheet「缺陷问题管理表」B 列「缺陷ID」。
- `2.风险登记册·关联变更ID` → 《项目变更跟踪表》sheet「项目变更跟踪表」B 列「变更ID」。
- 反向承接《亚远景_MAN3_TP_项目偏差问题清单》F 列「是否引发风险」/ G 列「风险ID」，风险ID 回填到该表。
- 支撑《横切_过程度量与目标定义》M-12「风险暴露度」取数（E 列可能性、F 列影响、G 列风险等级、N 列状态）。

**建议配置项登记名称：** 《风险登记册（含风险评估准则与风险评审记录）》；管理方式「版本管理」；负责角色「项目经理」；状态「正式发布」。

## 二、SUP.1_评审记录_V1.0.xlsx

**对应缺口：** P0 序号 49，过程域 SUP.1，证据要求「评审实施记录与问题闭环」，判定「缺失」。

> 原缺口文字：只有“计划”，没有“记录”：无评审签到、无检查单结果、无问题关闭证据；评估必抽样

> 补齐动作原文：新建《评审记录》模板（含检查单结果/问题ID/关闭状态），或复用不符合项跟踪表

**补齐字段（4 个业务 sheet）：**

- `1.评审基本信息`：评审ID、工作产品名称、工作产品版本（配置项ID）、评审类型（同行评审/走查/正式评审，下拉）、评审日期、主持人、参与者及角色、检查单标识、评审计划ID（引用 SUP.1 评审计划）。
- `2.评审检查单`：检查项ID、检查维度（完整性/一致性/可追溯/可验证/编码规范，下拉）、检查项描述、结果（通过/不通过/不适用，下拉）、证据位置、检查人。
- `3.评审问题清单`：问题ID、严重度（严重/主要/次要/提示）、位置、问题描述、提出人、责任人、计划关闭日期、实际关闭日期、状态（开放/已修复/已验证/已关闭）、关联不符合项ID（SUP.1 不符合项跟踪表）、复评结论。
- `4.评审结论`：问题总数（跨表 `COUNTA` 公式）、已关闭数（`COUNTIF` 状态）、未关闭数（`IF/MAX`）、结论（通过/有条件通过/不通过，下拉）、放行决定、批准人、日期。

**外键关联：**

- `1.评审基本信息·评审计划ID` → 《亚远景_SUP1_TP_评审计划_V0.3》sheet「工作产品评审计划」的评审计划条目。
- `3.评审问题清单·关联不符合项ID` → 《亚远景_SUP1_TP_不符合项跟踪表_V1.2》sheet「不符合项跟踪表」B 列「序号」/D 列「不符合项内容」。
- `3.评审问题清单·问题ID` 被《横切_过程度量与目标定义》M-04「评审问题密度」引用。
- `4.评审结论·问题总数/已关闭数/未关闭数` 直接以 `'3.评审问题清单'` 为唯一真源，避免两套计数。

**建议配置项登记名称：** 《评审记录（含检查单与问题闭环）》；管理方式「版本管理」；负责角色「质量保证 / 评审主持人」；状态「正式发布」。

## 三、横切_过程度量与目标定义_V1.0.xlsx

**对应缺口：** P0 序号 63，过程域「横切」，证据要求「过程度量与目标定义（CL2 PA2.2 前提）」，判定「缺失」。

> 原缺口文字：月报/周报有数据，但没有“度量项清单+目标值+阈值+超限动作”的定义文件，CL2 会问“你怎么知道过程有效”

> 补齐动作原文：新建《过程度量与目标定义》，把入 Mod 库、评审缺陷密度、工时偏差、NC 关闭周期、覆盖度等设为目标值

**补齐字段（3 个业务 sheet，预填 18 条度量）：**

- `1.度量项清单`（11 列）：度量ID、所属过程域、度量项、计算口径（分子/分母公式化）、数据来源模板与字段（精确到 sheet+列名）、采集频率、目标值、警戒阈值、超限动作、责任人、对应 PA。
- `2.度量采集记录`（7 列）：度量ID、采集周期（YYYY-MM）、实测值、目标值、是否超限（是/否下拉）、数据证据链接、采集人。
- `3.超限与纠正措施`（11 列）：措施ID、度量ID、超限周期、偏差描述、原因、纠正措施、责任人、计划完成、实际完成、效果验证、状态（开放/进行中/已完成/已验证）。

**18 条度量及数据来源（均指向真实模板字段）：**

| 度量ID | 度量项 | 数据来源（模板 → sheet → 字段） |
|---|---|---|
| M-01 | 配置项入库率 | SUP.8 配置项状态统计报告 → C 计划配置项数 / D 实际受控数 / E 入库率 |
| M-02 | 正式发布率 | SUP.8 配置项状态统计报告 → F 正式发布管控数 / G 正式发布数量 / H 正式发布率 |
| M-03 | 不符合项关闭周期 | SUP.1 不符合项跟踪表 → I 检查日期 / O 实际关闭日期 / Q 状态 |
| M-04 | 评审问题密度 | SUP.1 评审记录 → 3.评审问题清单 A 问题ID/B 严重度；1.评审基本信息 A 评审ID |
| M-05 | 缺陷遗留密度 | SUP.9 缺陷问题管理表 → B 缺陷ID / K 缺陷等级 / W 状态 |
| M-06 | 单元用例执行率 | SWE.4 报告 → 3.单元测试分析报告 B10 用例总数 / C10 已执行 / E10 执行率 |
| M-07 | 单元用例通过率 | SWE.4 报告 → 3.单元测试分析报告 C10 已执行 / D10 通过 / F10 通过率 |
| M-08 | 结构覆盖度超标模块数 | SWE.4 报告 → 3.单元测试分析报告 B6 / E6 |
| M-09 | 工时偏差率 | SWE.4 报告 → 附4.工作量统计 D/E/F/G |
| M-10 | 需求变更率 | SUP.10 项目变更跟踪表 B/G/H + 需求追踪表 系统需求清单 B |
| M-11 | 追溯闭合率 | 需求追踪表 各清单 B 标识 / G 下游元素 / H 测试用例 |
| M-12 | 风险暴露度 | MAN.5 风险登记册 → 2.风险登记册 E/F/G/N |

**建议配置项登记名称：** 《过程度量与目标定义（含度量采集记录与纠正措施）》；管理方式「版本管理」；负责角色「项目经理 / 质量保证」；状态「正式发布」。

## 四、通用_验证报告_V1.0.xlsx

**对应缺口：** 覆盖矩阵中 SYS.4 / SYS.5 / SWE.5 / SWE.6 四类验证报告问题：

- P0 序号 15，SYS.4「集成验证结果与偏差处理」，判定「不足」：

  > 原缺口文字：无 SYS.4 专用报告模板，通用报告“附2 测试结果”与用例、需求之间无强制外键

- P0 序号 34，SWE.5「集成验证结果记录」，判定「不足」：

  > 原缺口文字：无 SWE.5 专用报告，接口测试与集成结果只能塞进通用报告，追溯链易断

- P0 序号 36，SWE.6「软件需求→用例→结果的闭合验证」，判定「不足」：

  > 原缺口文字：用例与结果分布在两个文件，缺“软件需求ID”列，无法闭合到需求

- P1 序号 17，SYS.5「系统验证结果记录与覆盖率」，判定「不足」：

  > 原缺口文字：率值有，但“被测项”口径未定义（按需求？按功能？），覆盖率不可复核

**补齐字段（5 个业务 sheet）：**

- `1.验证基本信息`：被测对象、适用过程域（SYS.4/SYS.5/SWE.5/SWE.6 下拉）、被测基线版本（配置项ID）、测试环境、工具与版本、执行日期、执行人、参考计划ID（引用对应 PA 的验证计划）。
- `2.追溯与结果汇总`：序号、需求ID、架构元素ID、详细设计ID、用例ID、执行结果（通过/失败/阻塞/未执行，下拉）、通过准则、实测值、证据链接、关联缺陷ID（引用 SUP.9，禁止另建ID）、执行日期。
- `3.覆盖率统计`：需求条目总数、已覆盖需求数、需求覆盖率、用例总数、已执行、执行率、通过率、失败数、阻塞数；每行含计划值、实际值、公式/口径。实际值全部以 `2.追溯与结果汇总` 为唯一真源，`IF/IFERROR` 防空。
- `4.问题与偏差`：问题ID（引用 SUP.9）、描述、严重度、状态、对结论的影响、偏差说明。
- `5.结论`：结论（通过/有条件通过/不通过，下拉）、遗留问题清单、放行建议、批准人、日期。

**强制外键：**

- 需求ID → 《亚远景_ENG_TP_需求追踪表》系统需求清单 / 软件需求清单 B 列。
- 架构元素ID → 《亚远景_SYS3_TP_系统架构设计说明书》3.系统静态架构设计，或《SWE2_TP_软件架构设计说明书》3.软件静态架构设计。
- 详细设计ID → 《亚远景_ENG_TP_需求追踪表》软件详设清单 B 列。
- 用例ID → SYS.4/SYS.5/SWE.5/SWE.6 对应验证计划/测试规范中的用例编号。
- 关联缺陷ID → 《亚远景_SUP9_TP_缺陷问题管理表》B 列「缺陷ID」，报告中不得另建缺陷编号，保证缺陷单一真源。
- 参考计划ID → 《亚远景_SYS4_TP_系统集成和集成验证计划》《亚远景_SYS5_TP_系统验证计划》《亚远景_SWE5_TP_软件组件验证和集成验证计划》《亚远景_SWE6_TP_软件验证计划》。

**建议配置项登记名称：** 《通用验证报告（SYS.4/SYS.5/SWE.5/SWE.6）》；按过程域派生实例分别登记，如《SYS.4 系统集成验证报告》《SYS.5 系统验证报告》《SWE.5 软件集成验证报告》《SWE.6 软件验证报告》；管理方式「版本管理」；负责角色「测试经理」；状态「正式发布」。

## 五、统一约定

- 所有业务 sheet 首行冻结（`A2`），首行为中英对照表头（中文 + 换行英文），并设置自动筛选。
- 每个业务 sheet 正文仅保留表头与 1 个「待填写」占位；每 sheet 的 1 行示例统一放在隐藏 sheet `示例（勿删）`，示例数据不进入正文。
- 风险等级、评审结论计数、覆盖率等公式统一使用 `IF/IFERROR`，空数据时返回空值，不产生 `#DIV/0!`；日期列留空并预设日期格式。
- 严重度/状态/执行结果列已配置条件格式配色；风险等级矩阵按低/中/高/严重静态着色。
- 未修改 `_uploads`、`_source_templates`、`templates_clean` 与覆盖矩阵，也未执行 git commit。
