# ASPICE 4.0 填写示例：BCM 氛围灯

> **示例数据，仅用于演示填写方式与追溯闭环，不得作为项目证据。**
> 需求内容取自原模板中的 BCM + RGB 氛围灯示例；ID 编号、责任人、代码路径等均为演示用途。

## 1. 文件清单

| 文件 | 说明 |
| --- | --- |
| `SYS.2_系统需求规格说明书_BCM氛围灯示例_V1.0.xlsx` | 基于清洗版 SYS.2 模板填写的 5 条系统需求（1 条一级 + 3 条二级 + 1 条一级诊断），含产品介绍、验证阶段与验证准则 |
| `ENG_需求追踪表_BCM氛围灯示例_V1.0.xlsx` | 承接 SYS.2，覆盖 涉众 → 系统需求 → 系统架构 → 硬件需求/设计 → 软件需求 → 软件架构 → 软件详设 的完整链路 |
| `ENG_测试规范_BCM氛围灯示例_V1.0.xlsx` | 5 条系统级测试用例（`<需求ID>-TC-01`），与追踪表用例列一一对应 |
| `trace_report_BCM氛围灯示例.md` | `trace_check.py --bidirectional` 生成的校验报告 |
| `trace_report_BCM氛围灯示例.json` | 同一结果的机器可读版本，可直接接入 CI 门禁 |

三个工作簿均含首张「0.示例声明」页，正文数据中也标注了“示例数据，不作为项目证据”。

## 2. 追溯链设计

```text
STK-LGT-001/002 涉众需求
   ├─ SYS-LGT-001 调光 ──┬─ SYS-ARCH-LGT-001 BCM/LIN 主节点 ──┬─ SW-LGT-001 LIN 解析与寻址 ── SW-ARCH-LGT-001 ── SW-DD-LGT-001
   │                     │                                  └─ SW-LGT-002 调光控制     ── SW-ARCH-LGT-002 ── SW-DD-LGT-002
   │                     └─ SYS-ARCH-LGT-002 RGB 光输出模组 ──┬─ SW-LGT-003 温度补偿     ── SW-ARCH-LGT-003 ── SW-DD-LGT-003
   │                                                          ├─ SW-LGT-004 电压补偿     ── SW-ARCH-LGT-004 ── SW-DD-LGT-004
   │                                                          └─ HW-LGT-001 LED 驱动    ── HW-DES-LGT-001
   ├─ SYS-LGT-002 寻址 ──── SYS-ARCH-LGT-001
   ├─ SYS-LGT-003 温度补偿 ─ SYS-ARCH-LGT-002
   ├─ SYS-LGT-004 电压补偿 ─ SYS-ARCH-LGT-002
   └─ SYS-LGT-005 诊断 ──── SYS-ARCH-LGT-003 诊断处理 ── SW-LGT-005 故障诊断 ── SW-ARCH-LGT-005 ── SW-DD-LGT-005
```

每条「下游元素」都在目标行的「上游元素」中回指，满足严格双向闭环；软硬件分支在详设/LED
驱动电路处自然收尾（链尾）。

## 3. 复现校验

```bash
cd /workspace/aspice
python3 tools/trace_check.py \
  --trace "examples/ENG_需求追踪表_BCM氛围灯示例_V1.0.xlsx" \
  --cases "examples/ENG_测试规范_BCM氛围灯示例_V1.0.xlsx" \
  --bidirectional \
  --out "examples/trace_report_BCM氛围灯示例.md" --json
```

## 4. 实测结果（基线模式，退出码 0）

| 指标 | 数值 |
| --- | --- |
| 清单数 / 已分析 / 跳过 | 10 / 8 / 2 |
| 有效行（ID 非空） | 27 |
| 下游引用 / 断链 | 30 / **0** |
| 孤儿节点 | **0** |
| ERROR / WARN / INFO | **0 / 3 / 0** |
| 用例引用覆盖率 | 5/5（**100%**） |
| 双向闭环 | **开启并一致** |

3 条 WARN 均为示例文件的已知结构项，不影响追溯结论：

1. `0.示例声明` — 声明页没有表头，校验器按非清单页跳过；
2. `网络安全需求` — 原模板该页只有“网络安全目标 / 网络安全需求”文本列，没有 ID 列，
   无法建立索引（清洗版保留原结构，见覆盖矩阵缺口清单）；
3. `软件详设清单` — 原模板没有“下游元素”列，按链尾处理（其“上游元素”列已补齐）。

若使用 `--strict`，上述 3 条 WARN 会使退出码变为 1。建议先在模板层面补齐网络安全
需求 ID 列与详设下游列（如代码/单元测试覆盖关系），再启用严格门禁。

## 5. 数据来源与边界

- SYS.2 的「2.产品介绍」文字与「3.系统需求」的调光功能描述取自原模板
  `亚远景_SYS2_TP_系统需求规格说明书_V1.0.xlsx` 的既有示例（BCM 为 LIN 主节点、
  RGB 模组为从节点，支持寻址、温度补偿、电压补偿、诊断）。
- 追踪表中的 `STK-* / SYS-* / SYS-ARCH-* / HW-* / SW-* / SW-DD-*` 编号为演示编号，
  不是原模板的 `ProjectID_*` 编号。
- 测试用例的步骤与期望结果为演示性描述，未代表任何真实测试执行记录；报告中的
  “用例覆盖率”只证明引用关系完整，不等于测试已执行或已通过。
