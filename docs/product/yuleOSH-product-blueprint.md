## 1. 产品愿景与定位

### 1.1 一句话定位

> **AI 原生嵌入式开发平台：从需求到固件到合规证据包，全流程自动化。**

### 1.2 定位演进逻辑

| 版本 | 定位 | 问题 |
|---|---|---|
| v1 | AI-Powered Embedded Development Pipeline | 太泛，无合规锚点 |
| v2 | 一站式 ASPICE 合规开发平台 | "一站式"承诺过高 |
| v3 | 嵌入式软件合规开发自动化平台（SWE 辅助） | 只卖合规，浪费 AI 能力 |
| **v4（本说明书）** | **AI 原生嵌入式开发平台，合规内置** | 开发解决"快"，合规解决"稳"，互为杠杆 |

### 1.3 为什么是"双引擎"而不是单选

- **主引擎（开发）**：AI Agent 流水线从 spec 生成架构 → 代码 → 测试 → 审查，把嵌入式开发从"周"压缩到"小时"（dogfood 实证：UART 驱动 3 天 → 2 小时）
- **副引擎（合规）**：ASPICE SWE.1~6 证据包、追溯矩阵、MISRA、覆盖率门禁作为流水线的**自动副产物**——不需要额外工作，合规就产生了
- **杠杆效应**：客户为"快"买单（省人力），为"稳"续费（过审计）。两个价值点互相强化，不是二选一

### 1.4 产品原则

1. **合规是副产物，不是功能**——证据包从流水线自动生成，不要求用户额外操作
2. **AI 辅助，人工把关**——关键环节（架构决策、代码合入）保留人工审批，不做全自动黑盒
3. **不替代工具，编排工具**——寄生 Jenkins/Vector/Jira 生态，做编排中枢而非另一座孤岛
4. **开箱即信**——`pip install yuleosh && yuleosh init && yuleosh pipeline run` 三命令跑通

## 2. 目标市场与客户分层

### 2.1 市场选择

**策略：汽车电子打标杆（80%），泛嵌入式放量（20%）。**

| 市场 | 角色 | 需求强度 | 客单价 | 决策链 |
|---|---|---|---|---|
| 汽车电子（OEM/Tier1/Tier2） | **灯塔客户（80% 投入）** | ASPICE 合规刚需 | 高（¥98K+） | 长 |
| 工控/医疗/机器人 | **现金流客户（20% 投入）** | MISRA/CI/自动化需求 | 中（¥599-¥98K） | 中 |
| 消费电子/物联网 | **放量客户** | 开发效率需求 | 低（Free/¥599） | 短 |

**依据**：
- 汽车电子：ASPICE 审计是刚需，中国企业开发周期 24-30 个月（全球最短），对效率工具最迫切
- 泛嵌入式：MISRA C、覆盖率门禁、CI 自动化是普适需求，不依赖 ASPICE 概念也能卖
- 数字钥匙市场（yuleDKCS 同生态）：中国 RMB 30 亿+，YoY 58.7%，是垂直样板

### 2.2 客户分层

| 优先级 | 画像 | 数量级 | 打法 |
|:------:|:-----|:------:|:-----|
| 🔴 P0 | 新势力车厂 + Tier1 数字钥匙供应商 | ~25 家 | 标杆项目 + PoC |
| 🟡 P1 | 传统车厂转型 + 嵌入式 ODM/外包 | ~120 家 | 合规痛点切入 |
| 🟢 P2 | 工控/医疗/机器人团队 | ~500 家 | 效率工具切入 |
| ⚪ P3 | 个人开发者/开源社区 | 不限 | 流量漏斗 |

### 2.3 三类用户画像（决策者视角）

| 画像 | 核心痛点 | yuleOSH 价值 | 一句话 |
|---|---|---|---|
| 🛡️ 质量经理 | 审计准备 1-2 周，Excel 追溯混乱 | 证据包一键生成，审计应答 5 分钟 | "审计准备从 2 周变 5 分钟" |

## 6. 竞争格局与差异化

### 6.1 竞品地图

```
                    通用 AI 编码
                    (Copilot/Cursor/Claude Code)
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
  嵌入式工具链             │             合规工具
  (Vector/ETAS/LDRA)       │          (手工三件套:
        │                  │         Jenkins+Excel+Jira)
        └──────────────────┼──────────────────┘
                           │
                    ┌──────▼──────┐
                    │  yuleOSH     │
                    │  唯一的      │
                    │ AI+合规+嵌入 │
                    │  三者交叉    │
                    └─────────────┘
```

### 6.2 差异化三支柱

1. **全链条唯一性**：没有竞品同时覆盖"需求引擎 → AI 开发 → 三层测试 → 合规证据"完整闭环
2. **嵌入式领域知识**：MISRA 规则库、AUTOSAR 集成、QEMU SIL、交叉编译——通用 AI 工具不具备
3. **合规自动副产物**：证据包是流水线的自然输出，不是额外功能——竞品需要单独采购合规工具

### 6.3 竞品威胁与应对

| 威胁 | 严重度 | 应对 |
|---|---|---|
| Vector/MathWorks 推出 AI 方案 | 中 | 大厂组织惯性，全链条覆盖是盲区；初创敏捷 |
| 通用 AI 编码工具下探嵌入式 | 中 | 深耕 MISRA/AUTOSAR/合规知识，非通用能力 |
| ASPICE 认证需要 certified assessor | 高 | 定位"合规辅助"而非"合规认证"，工具+咨询双驱动 |
