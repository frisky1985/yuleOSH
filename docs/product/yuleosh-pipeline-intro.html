What is it

不是又一个 AI 代码生成器

yuleOSH 把「生成代码」约束进一条可审计的合规流水线：每个阶段有专属 Agent、每个转换有评审门禁、每个门禁有机器校验 —— AI 负责产出，平台负责保证产出合规。

🧭

Doc-Driven 全流程

Spec → S.U.P.E.R 分析 → PRD → 架构 → 开发计划 → 代码 → 测试规划 → 评审 → CI → 证据包。需求从文档出发，每个产物落盘可追溯。

🛡️

护栏优先于生成

行为护栏 G-01~G-17、P0 关键安全门禁、部署回滚联动。生成代码必须通过真实测试与静态合规检查，失败自动回滚，绝不污染主干。

📦

证据包一键交付

追溯矩阵、验收矩阵、MISRA 报告、覆盖率报告、合规 ZIP 证据包 —— 审计要什么，pipeline 交付什么。

The Pipeline

24 步 · 10 Gate · ASPICE V 模型

左侧规格化（SWE.1 需求 → SWE.3 设计）、底部实现与单元验证（SWE.4）、右侧验证（SWE.5 集成 → SWE.6 合格性）。每一步都产出落盘产物，红色为阻断门禁，粉色为外部 Agent 独立验证。

Core Mechanisms

合规不是口号，是机器校验

平台把「评审标准」从人肉记忆变成可执行的机器检查 —— 契约抽取、护栏体系、SHALL 清单注入，都是确定性逻辑，可单测、可回归。

Contract

Spec 契约抽取与机器校验

spec_contracts.py 从叙述性 spec 抽取机器可读 JSON：接口签名、行为护栏 G-01~G-17、参数边界、NVM 布局、需求覆盖。spec-check 步骤做确定性完整性校验，不通过直接 RED —— 合规审查从 LLM 人审迁移到机器检查。

Guardrail

行为护栏体系

ChangeSet 变更集模型统一备份/回滚；codegen-deploy 部署前备份、门禁失败自动回滚；TestRunner 协议统一 C / Python / Go / 集成测试执行。只有真实行为回归才触发回滚，覆盖率低/规范违规不误伤基线。

Ground Truth

官方 SHALL 清单注入

评审 prompt 注入从 spec 结构化提取的「官方 SHALL 清单」作为单一事实来源 —— 消除 LLM 自报 SHALL 数量与 spec 正文的分歧（曾导致 85 vs 41 的评审误判）。

Cache

失败产物防复用

step_cache 对失败状态（FAILED_STATUSES）不缓存、查找视为 miss —— 修复后的重跑永远不会复用失败产物；合法 skipped 仍缓存，避免无效重算。

Codegen

代码生成自动修复环

D3 生成 → 编译验证 → 自动修复循环；seed_contract 保护现有公共函数不被删除；behavior_verify 在生成循环内临时部署并跑真实测试，回归即时反馈给 LLM。

Evidence

证据引擎

追溯矩阵（需求 ↔ 测试 ↔ 代码）+ 验收矩阵 + 覆盖率报告，一键打包合规 ZIP 证据包 —— ASPICE 审计的完整交付物。

Loop

四闭环循环工程

缺陷 → Spec 追溯；现场缺陷 → FMEA 安全分析；KPI → RCA → 改进工单；知识图谱置信度自演进。每个闭环都是「发现问题 → 反哺规范 → 回归验证」。

KG

知识图谱追溯

SQLite BFS / PostgreSQL 递归 CTE 支撑的图存储，做影响分析、增量 CI 钩子、Merge Gate 图一致性 / 置信度检查。

Mixed

混合语言合规

嵌入式 C MISRA 门禁扩展到 Go / Python 项目（project_language: mixed）；实测 yuleDKCS 690 → 0 MISRA violations（57 文件；cppcheck C:2012 扫描 + C:2023 规则集映射）。
