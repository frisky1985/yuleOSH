# 变更请求管理 (SUP.10)

## 变更管理流程

1. **提交**: 填写变更请求表（CR-ID、标题、描述、理由）
2. **登记**: 分配唯一 ID (CR-xxx)，记录提交日期与提交人
3. **分析**: 评估影响范围（受影响的需求/设计/代码/测试）
4. **决策**: CCB (变更控制委员会) 审批 — 批准/拒绝/延期
5. **实施**: 按批准范围执行变更
6. **验证**: 确认变更实施正确，追溯矩阵更新
7. **关闭**: 更新 CR 状态为「已实施」或「已关闭」

## 变更控制委员会 (CCB)

| 角色 | 成员 | 职责 |
|------|------|------|
| CCB 主席 | 项目经理 | 主持评审会议，最终决策 |
| 技术代表 | 系统架构师 | 评估技术影响 |
| QA 代表 | QA 经理 | 评估质量影响 |
| 需求代表 | 需求工程师 | 评估需求影响 |
