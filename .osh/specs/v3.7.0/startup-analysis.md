# Startup Analysis — yuleOSH v3.7.0（Track1 + Track4）

> 版本: v3.7.0 · 基线: v3.6.1 (28ef25a) · 日期: 2026-08-02
> 方法: Superpowers S.U.P.E.R.（Situation / Understanding / Problem / Evaluation / Resolution）
> 决策: 老板 2026-08-02 已确认方案 A（Track1 + Track4 → v3.7.0；Track2 → v3.8.0；Track3 → v3.9.0）

---

## S — Situation（现状）

- yuleOSH v3.6.1 (28ef25a)：P0×4 已全部真修复，P1 11 项高质量落地，基线 **9794 passed / 0 failed**，覆盖率 ≥84.10%。
- 综合评分 7.3/10（较上次 6.2 提升），已"可内部使用"，**暂不建议对客户演示**。
- 剩余问题：Warning×13 中 7 项（W1-W7）属单体小修/行为修正，可直接做；杂项 4 项（M1-M4）小成本；架构收敛（Track2）与前端安全（Track3）面大风险高。
- 老板已拍板方案 A：**快赢优先**，2-3 天交付 v3.7.0 = Track1 + Track4。

## U — Understanding（理解）

**v3.7.0 的本质**：不是新功能版，而是"质量巩固 + 行为修正"版——把 13 个 Warning 里**可独立、低风险、高收益**的 7 项 + 4 个杂项一次性清掉，让系统在对外演示前的"信任基线"再上一个台阶。

**为什么这些项值得现在做**：
1. W1（do_GET 静默降级）：故障掩盖类——监控看到 200 误判健康，排障成本高，且与已修的 do_POST 不一致，属"修一半"遗留。
2. W2（限流竞态）：安全漏洞类——并发爆破可绕过 10 次/5min 上限，IP 表无限增长 DoS。攻击面真实存在。
3. W3（swe6 假阳性）：**信任问题**——对客户/审计方展示的合规报告是硬编码 True，一旦被识破，整个质量体系信誉受损。
4. W4（迁移漏网）：明文 token 滞留 DB，安全收尾不彻底。
5. W5（sandbox 收紧）：行为变更遗留——P2-2 已收紧但没评估插件兼容性，属于"改了但没闭环"，不评估可能静默破坏既有插件。
6. W6（缓存无 owner 隔离）：跨用户信息泄露（预览报告含代码结构）。
7. W7（无 timeout + shell=True）：挂起 DoS + shell 注入残留。

**与 v3.8/v3.9 的关系**：Track1/Track4 是"手术刀"，Track2 是"大手术"，Track3 是"换血"。三者独立，快赢先行不影响后续架构收敛（W2/W5/W6 的改动为 Track2 认证/沙箱收敛提供更稳的地基）。

## P — Problem（问题定义）

**一句话**：v3.6.1 的 13 个 Warning 中，7 个可独立修复项 + 4 个杂项，如何在 **2-3 天内**安全落地，**不引入回归、不破坏基线 9794/0、覆盖率不降**，并让每项都有可复验的验收标准？

**关键矛盾**：
- 快（2-3 天）vs 稳（行为变更项 W2/W5/W6 回归风险高）；
- 真实化（W3 去模拟）vs 兼容（CLI 输出/报告字段变化）；
- 收紧（W5/W6）vs 兼容（既有插件/缓存语义）。

**非目标**：Track2 架构收敛、Track3 前端安全、yuleASR-Configurator、SEC-W3（仅核查不修复，异常则升级）。

## E — Evaluation（方案评估）

**方案空间**（老板已选 A，此处记录评估过程供回溯）：

| 方案 | 内容 | 工期 | 优点 | 缺点 |
|------|------|------|------|------|
| A（已选） | v3.7.0=Track1+Track4；v3.8=Track2；v3.9=Track3 | 2-3 天 | 快赢、风险隔离、每版可独立验收 | 架构债多挂两个版本 |
| B | 全量打包一个版本 | 10-12 天 | 一次到位 | 回归面巨大、交付延迟、风险不可控 |
| C | 按优先级挑项 | 不定 | 灵活 | 范围蔓延、验收混乱 |

**A 优于 B/C 的理由**：
- 11 项中 8 项为独立小修（W1/W3/W4/W7/M2/M3/M4 + 半项 M1），可并行开发；
- 行为变更项 W2/W5/W6 集中在 3 个文件，可单独 PR + 重点回归；
- 每项收益独立可量化（W3 信任修复、W2 安全修复、W6 隐私修复），验收矩阵可逐项对账；
- 与 Track2 解耦：Track2 的认证合一反而受益于 W2 的锁先行落地。

**内部方案要点**（对每一项）：
- W1: 异常路径分流 JSON 500 / 500 页 + exc_info（对齐 do_POST）。
- W2: `_ThreadSafeDict` 复用 + IP 表概率清理 + **测试兼容适配**（高风险点，前置 grep）。
- W3: 复用 `spec.validate.parse_spec` 真实计数 + `--report` 注明来源。
- W4: Python 侧 `re.fullmatch(r"[0-9a-f]{64}")` 过滤（比 SQL GLOB 稳）。
- W5: 先审计 plugins/（附录 A 清单）→ `extra_read_dirs` 读白名单（写权限严格隔离）。
- W6: 缓存键 `(user_key, url_hash)`；user_key=user_id 或 IP hash。
- W7: 批量 `timeout=30/120-300` + demo_uart 去 shell（argv 形式）。
- M1: html.parser 白名单（路线 A 推荐）或正则+补负例（路线 B）——**需小明选型确认**。
- M2: hash 文件名 → immutable；HTML → no-cache。
- M3: server.py 引用 auth.py 单一来源（注意循环导入）。
- M4: `urlsplit(path).path` 剥离 query 后匹配白名单。

## R — Resolution（决议）

### 为什么做（Why）
| 类别 | 项 | 价值 |
|------|-----|------|
| 安全 | W2, W5, W6, W7 | 堵并发爆破、插件越权读、跨用户缓存泄露、挂起 DoS、shell 注入 |
| 信任 | W3, M1 | 合规报告真实化、XSS 纵深防线补强 |
| 正确性 | W1, W4 | 故障不再掩盖、迁移彻底 |
| 工程卫生 | M2, M3, M4 | 缓存头、单一来源、白名单 query 匹配 |

### 优先级（P0 顺序）
1. **W2 + W6**（安全漏洞类，先做，独立 PR）
2. **W1 + W3 + W4**（正确性/信任类，可并行）
3. **W5**（需前置插件审计，第三步）
4. **W7**（批量机械改动，需全量回归兜底，可与 2 并行）
5. **M1-M4**（杂项，最后收尾）

### 成功标准（Done 定义）
1. 11 项全部有正例 + 负例测试，`acceptance-matrix.md` 全部 ✅；
2. 全量回归 ≥ 9794 passed / 0 failed（v3.6.1 基线）只增不减；
3. 覆盖率 ≥84.10% 不降；
4. 行为变更三件套（W2 限流锁语义、W5 sandbox 收紧、W6 缓存键）均有专项回归 + 兼容适配记录；
5. W5 插件审计清单（spec-delta 附录 A）回填完整；
6. M1 选型（A/B）经小明确认并记录；
7. SEC-W3 核查完成（默认值存在→升级上报；不存在→记录）。

### 风险与缓解
| 风险 | 等级 | 缓解 |
|------|------|------|
| W2 测试直操模块级 dict 导致大面积改测试 | 高 | 前置 grep 全部用法；`_ThreadSafeDict` 补 `__len__`/`keys()` 等最小兼容面 |
| W5 收紧破坏既有插件（静默回归） | 高 | 审计先行（附录 A）；白名单显式声明；现有 sandbox 测试保持 |
| W6 缓存语义变化（跨用户不再命中） | 中 | 读取路径不依赖缓存键（preview_id 路径不变）；同用户命中保留；NAT 同 IP 限制文档化 |
| W1 SPA fallback 依赖异常兜底 | 中 | 确认 fallback 在 handler 正常路径；异常仅真错误 |
| M1 html.parser 吞掉代码样例 `<vector>` 文本 | 中 | 自定义 parser 保留裸 `<` 文本；负例覆盖；路线 B 兜底 |
| M3 循环导入 | 中 | 延迟导入或导入图审查 |
| W7 超时值误杀正常构建 | 中 | 编译类 120-300s；全量回归重点 CI/pipeline 测试 |
| W3 用例计数口径与 spec 格式不符 | 中 | 开发时先跑真实 spec 验证计数；口径以 scenarios 为准并注明 |

### 验收负责人
- **开发**: 小克（按 spec.md SHALL 条款 + acceptance-matrix.md 测试清单）
- **复验**: 小马（独立跑测试 + 审查行为变更项 + 插件审计清单核验）
- **终审**: 小明（分歧裁决、M1 选型、SEC-W3 升级判定）

### 时间盒
- 预估 2-3 天（Track1 ~1.5d + Track4 ~1d + 回归/复验 0.5d）。
- 每批（P0 顺序 1-5）后跑局部回归（`tests/test_backlog_p1_v350.py tests/test_ui_server_deep.py tests/test_cli_main_adv_unit.py tests/test_kb_sanitize_xss.py -q`），收尾全量回归。
